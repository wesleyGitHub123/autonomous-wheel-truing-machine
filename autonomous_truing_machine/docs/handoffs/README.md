# Handoffs

One file per delegated task, `<task>.md`, written by the lead and committed on `main` **before** the
task is dispatched so it exists in the delegate's worktree. The rule, the routing and the template
are in `../DELEGATION.md`; the delegate's standing rules are in `.clinerules/` at the repository root.

Lifecycle: the lead writes and commits the handoff, the delegate appends its return report on its
`wip/<task>` branch, the lead reviews, and on acceptance squash-merges the branch so the finished file
(handoff and report together) stays here as the audit trail. A dropped or taken-back task keeps its
file with the outcome noted.

Nothing here is evidence about the campaign. A report is a delegate's claim, and only what the lead
re-ran and reviewed becomes a claim of the project.

Empty until the first real delegation.
